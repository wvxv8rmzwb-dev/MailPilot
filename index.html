Fonctionnement

Trois étapes, c'est tout

01

Installe le daemon

Un npm start et MailPilot tourne en local : scheduler d'envois + petit dashboard web.

npm install && npm start
02

Branche Claude Code

Une commande pour connecter MailPilot à Claude Code via MCP. 15 outils apparaissent.

claude mcp add mailpilot -- npm run mcp
03

Parle-lui

Claude compose, personnalise et programme. Le daemon envoie à l'heure, même Claude fermé.

« Programme un mail pour demain 9h »
« Programme un mail pour demain 9h à ma liste Prospection OF, sujet "Bonjour {prenom}, une question sur {entreprise}" »
— toi, dans Claude Code. C'est le seul geste à faire.
Fonctionnalités

Pensé pour l'envoi sérieux

Un mail par personneChaque destinataire reçoit son propre mail. Jamais de liste visible, jamais de « To: 87 contacts ».
Personnalisation{prenom}, {entreprise}… chaque mail est rendu contact par contact, avec aperçu avant envoi.
ProgrammationDate, heure, même fenêtre fermée : le daemon local déclenche, pas un cloud qui peut fermer.
Anti-spam intégré100 contacts max par campagne, 3 s entre chaque mail, cap quotidien configurable par compte.
Fenêtre d'envoiPar défaut 08:00–20:00 : tes mails n'arrivent jamais à 3h du matin, et le compte ne se fait pas flagger.
Relance des échecsErreur réseau ? Retry automatique avec backoff. Boîte pleine ? Un clic pour relancer les échecs.
DésinscriptionMention en pied de mail + header List-Unsubscribe : conforme LCEN/CGPR, bon signal pour les boîtes.
Modèles & exportSauvegarde tes mails types, recharge-les en un clic, exporte chaque campagne en CSV.
Dashboard localComposer, campagnes, contacts, comptes SMTP — tout sur localhost:3777, rien dans le cloud.
100% local, 100% à toi

Tes mots de passe SMTP sont chiffrés (AES-256-GCM) sur ta machine. Tes contacts et campagnes vivent dans une base SQLite locale. Aucun compte à créer, aucune donnée qui transite par un serveur tiers. Si MailPilot disparaît demain, tu as déjà tout sur ton disque.
